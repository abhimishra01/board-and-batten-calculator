# Design and SEO review: board-and-batten-calculator
Reviewer: Miranda (independent). Date: 2026-10-20. Build: `astro build --outDir dist-design`, served on port 4436, viewed with playwright-cli at 1280 and 390, light and dark, plus print media.

## Scores
Lighthouse (local static server, so the compression and cache hints are server artefacts and not counted):

| Run | Performance | Accessibility | Best practices | SEO |
|---|---|---|---|---|
| Mobile | 100 | 98 | 100 | 100 |
| Desktop | 100 | 98 | 100 | 100 |

LCP 1.4 s mobile, CLS 0, TBT 0 ms, page weight 75 KiB (HTML 35 KB, one CSS 25 KB, one JS 13 KB, no images on the page). The only failed audit is heading order (see table).

## Verdict
Clearly better than the competitors in the research. The only real rival works in metric only, with no drawing and no cut list. This tool has a to-scale drawing, numbered marks to 1/16", a cut list, a stock-length table with waste, rails, metric, print and a copy button. The look is clean and consistent in both themes. The article tables were checked by hand and are correct.

Must-fix before launch: 2 (rows 1 and 2). Should-fix: 9. Nice to have: the rest.

## Findings
| # | Severity | Area | Finding | Fix |
|---|---|---|---|---|
| 1 | Must | SEO | The meta description, og:description, twitter:description and the WebApplication JSON-LD description on the home page all read "A free online ruler that works in your browser... Measure in inches or centimetres." This is the unedited template text (`site.config.ts` `description`). It is wrong for this tool, it hurts the Google snippet, and "centimetres" is British. The 404 page repeats it. | Set `description` to about 150 characters in US English, for example "Free board and batten spacing calculator. Get the exact gap, a mark for every batten, a to-scale drawing and the boards to buy." |
| 2 | Must | Print | Printing is a core feature, but the marks table sits in a `max-h-96 overflow-auto` box. In print media this clips it. With 20 battens the table is 763 px tall and the box is 384 px, so half of the marks never reach the paper. Tested in print emulation. | Add to the print CSS: `#marks` parent `max-height:none; overflow:visible`. Also remove the max height on the other table wrappers in print. |
| 3 | Should | Error state | Errors appear at the top of the results column. On a phone that is below the whole form (about y=1060 px), so a user who clears the wall width sees nothing change near the field, only dimmed results far below. No field gets `aria-invalid` (the CSS for it exists but nothing sets it). | Show the message next to the form (above the Units row on phone), set `aria-invalid="true"` and `aria-describedby` on the bad field, and scroll or focus on error only if it is off screen. |
| 4 | Should | Phone use | The result is about 1000 px below the first input. The user changes a number and has to scroll to see the effect. There is no sticky summary. | On phones, add a sticky bar at the bottom with the gap and the batten count, or a "Jump to result" link. Alternative: put the inputs in two steps. |
| 5 | Should | Accessibility | The scrolling marks table is not keyboard reachable (no `tabindex="0"`, no role or label). A keyboard user cannot scroll to marks 11 and up. Lighthouse does not catch this. | Fix with row 2 (no inner scroll). If a scroll box stays, add `tabindex="0" role="region" aria-label="Marks from the left"`. |
| 6 | Should | SEO, structure | Heading order: H1 jumps to four H3 elements (Marks, Rail marks, Cut list, Boards to buy) before the first H2. Lighthouse fails "heading-order". The outline is also weak for search: the tool part has no H2. | Make those four headings H2 with the same styling. Optional: one H2 above the tool results, for example "Your board and batten layout". |
| 7 | Should | SEO, depth | One page only. The article has about 750 words and good formula and example sections. The long tail the research lists ("for entire room", "how far apart", "cut list") is covered only by one article. There are no pages for common wall sizes. | After launch, add static pages from the same tool, such as "board and batten spacing for a 10 foot wall" and "for a 12 foot wall", each with the answer in the first line. Link them from the article table (each row to its page). |
| 8 | Should | SEO, internal links | The article has no links to the tool or to other pages. The sitemap has 5 URLs. The page also has a BreadcrumbList with one item, which adds nothing. | Link "the tool" in the first paragraph and the worked example to `#tool` (and preload the example values by URL hash, which the tool already supports). Remove the single-item BreadcrumbList. |
| 9 | Should | Drawing, phone | On a 390 px screen the drawing text renders at about 9.4 px (batten numbers, "13 1/4" gap", "12'"). That is hard to read. The wall height label is rotated, and the foot mark looks like a dash ("-8"). | Raise the minimum font to about 12 px in the SVG (scale the font with the viewBox width). Write the height label as "8 ft" or place it horizontally. |
| 10 | Should | Layout | Duplicate links. About, Privacy, Terms and Contact appear in a small row right under the tool and again in the footer, and the header repeats About and Contact. The row under the tool adds noise between the tool and the article, and its links are 20 px tall (small tap targets). | Remove the row under the tool (the footer has them). |
| 11 | Should | Share | The tool writes all settings to the URL hash, but there is no button to copy the link. The research lists a shareable link as a feature, and DIY users send layouts to a partner. Users cannot know the link works. | Add a "Copy link" button beside "Copy cut list and marks" and a "Save drawing as PNG" button (the research also lists PNG). Not blocking. |
| 12 | Should | Print content | The printed page hides the form, so the sheet does not show the inputs (wall height, batten width, ends on or off, rails). The drawing shows the totals, but the batten width and the mode are missing. A printout without the batten width is hard to use in the garage. | Add one print-only line: "Wall 12' x 8', battens 2 1/2" wide, batten at each end, 10 battens." |
| 13 | Nice | Desktop layout | The left column ends after the two checkboxes and leaves a large empty area beside the marks and cut list. Rails, when switched on, fill some of it. | Make the form column sticky on large screens so the inputs stay in view while the user reads the marks. |
| 14 | Nice | Drawing | With 20 battens the number labels thin out (1, 3, 5...) but "19" and "20" touch at the right edge. The wall is plain white, with no window or door boxes (research idea, not in this spec). | Drop the label when two are closer than 1.2 times the text width. Keep windows and doors for a later version. |
| 15 | Nice | Controls | Chips, segment buttons and the count field are 40 px tall (the step buttons are 44 px). Phones prefer 44 to 48 px. | Raise `.chip` and `.seg span` to `min-height:2.75rem`. |
| 16 | Nice | Metric | In metric mode the hint under the batten width still reads "A 1x3 board is 2 1/2 in wide, a 1x4 is 3 1/2 in." Switching from 12 ft gives 365.8 cm and 6.4 cm, which are odd numbers to a metric user. | Show the hint as "6.4 cm and 8.9 cm" in metric. Round converted values to the nearest 0.5 cm, or keep the exact value but say it came from feet. |
| 17 | Nice | Content | Writing is clean, plain US English, no dashes, no AI tells I could find. Two small things: "Doing the math first removes the problem." is a closer, and the table intro "The count is the one that lands closest to the gap in the heading" is hard to parse. | Cut the closer. Rewrite the second: "Each count gives the gap nearest 12 inches or 16 inches." |
| 18 | Nice | Content gaps | The article does not say how high to place the top rail, how to handle windows, doors and outlets, or how to plan an alcove. Searchers for "entire room" will look for it. | Add a short "Whole room" section: measure each wall on its own, keep the same gap on all walls, and start at a corner. |
| 19 | Nice | FAQ | The 8 questions are real and the answers are short and correct, and they match the FAQPage JSON-LD. Google now shows FAQ rich results rarely, so do not count on them. | Keep. Add "How many battens for a 10 foot wall?" with a link to the future size page. |
| 20 | Nice | Brand | Logo and favicon are good: four bars and a rail on a green tile, readable at 32 px, consistent in the header, the og.png (1200x630, clean) and the manifest. The brand name in the header ("Board & Batten") differs from the site name used in titles ("Board and Batten Calculator"). | Optional: use the same name everywhere. |
| 21 | Pass | SEO technical | Title (49 characters) and H1 match the main query. Canonical is correct with a trailing slash. JSON-LD parses (WebApplication, BreadcrumbList, FAQPage). Sitemap lists 5 URLs and omits the 404. robots.txt allows all and points at the sitemap. The `_headers` file noindexes `*.pages.dev`. Subpages have their own title and description. | None. |
| 22 | Pass | Accessibility | Skip link, visible focus ring, every field has a label (some screen-reader-only), radio groups have names, the drawing has `role="img"` with a text alternative, the live region announces results, dark mode contrast is fine, reduced motion is handled. | None, apart from rows 3, 5 and 6. |
| 23 | Pass | Performance | No layout shift (the results box has a fixed minimum height), no images, no third-party scripts, 75 KiB in total. | None. |
